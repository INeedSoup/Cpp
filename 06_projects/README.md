# 06 — Projects

## Goal

Move from isolated syntax to complete programs. Read each program once, run it, then trace how data flows between its helper functions. The important lesson is organisation: input, rules, state, and output should not all be mixed into one block.

| Project | Concepts combined | Challenge |
| --- | --- | --- |
| 01 Banking and RPS | menus, loops, validation, functions, formatting, randomness | Add a transaction history or a “play again” loop. |
| 02 Quiz game | arrays, nested loops, character conversion, scoring | Store the quiz in structs and randomise question order. |
| 03 Luhn validator | strings, algorithms, reverse iteration, boolean rules | Allow hyphens as separators and show the calculated checksum. |
| 04 Tic-Tac-Toe | arrays, loops, validation, functions, random moves | Add a replay option, then write a smarter computer move. |

## Project checklist

Before calling a project complete, verify invalid input, empty input, boundary values, normal success cases, and repeated use. Then describe each function's responsibility in one sentence.
